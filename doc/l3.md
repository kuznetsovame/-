## Описание задания

Задача № 6: "Robots ".

Создание роботов-насекомых является трудоемкой задачей.Инженеры занимаются проектированием схем в чертежных средах, разрабатывают компоненты для сборки роботов с помощью станков. Программисты отвечают за написание кода для программного обеспечения, которое управляет роботами. Дизайнеры создают внешний вид робота с помощью программных сред. Биологи изучают модель поведения насекомого и отражают результаты в отчетах. Наконец, специалисты по бионике описывают поведение насекомого в виде дифференциальных уравнений, которые программисты добавляют в программное обеспечение.

## Спецификация OpenAPI

Спецификация OpenAPI сформирована в папке `oas` проекта.

## Выводы

1. Разработана **OpenAPI спецификация** (YAML, версия 3.0.0) для системы разработки и производства роботов-жуков сельскохозяйственного назначения

2. Описаны **19 эндпоинтов**, покрывающих все 7 изолированных контекстов, выделенных в ЛР1:
   - Engineering Context (инженеры) — 5 эндпоинтов
   - Design Context (дизайнеры) — 1 эндпоинт
   - Biology Research Context (биологи) — 2 эндпоинта
   - Bionics Context (бионики) — 2 эндпоинта
   - Software Context (программисты) — 3 эндпоинта
   - Manufacturing Context (производство) — 3 эндпоинта
   - Assembly Context (сборщики) — 3 эндпоинта

3. Определены **схемы данных** для каждого эндпоинта:
   - Prototype (прототип)
   - BiologyReport (биологический отчёт)
   - BionicEquations (дифференциальные уравнения)
   - Firmware (прошивка)
   - ManufacturingOrder (производственный заказ)
   - Component (компонент)
   - AssembledRobot (готовый робот)

4. Приведены **примеры запросов и ответов** для ключевых операций:
   - создание прототипа
   - загрузка биологического отчёта
   - преобразование отчёта в дифференциальные уравнения
   - генерация прошивки
   - создание производственного заказа
   - завершение сборки

5. Задокументированы **HTTP status codes** (200, 201, 400, 404, 422, 500)

6. Спецификация соответствует требованиям подхода **«Сначала API» (Design API First)** и может использоваться для:
   - генерации клиентских SDK
   - генерации интерактивной документации (Swagger UI)
   - макетирования (mock-up) сервисов
   - автоматизации API-тестирования

**Изученные технологии:** OpenAPI, REST API, YAML, Swagger, Design API First.
