## Описание задания

Задача № 6: "Robots ".

Создание роботов-насекомых является трудоемкой задачей.Инженеры занимаются проектированием схем в чертежных средах, разрабатывают компоненты для сборки роботов с помощью станков. Программисты отвечают за написание кода для программного обеспечения, которое управляет роботами. Дизайнеры создают внешний вид робота с помощью программных сред. Биологи изучают модель поведения насекомого и отражают результаты в отчетах. Наконец, специалисты по бионике описывают поведение насекомого в виде дифференциальных уравнений, которые программисты добавляют в программное обеспечение.

## Спецификация OpenAPI

Спецификация OpenAPI сформирована в папке `oas` проекта.

## Выводы

1. Разработана **OpenAPI спецификация** (YAML, версия 3.1.0) для **универсальных роботов-насекомых** (поддерживаются любые виды: жук, муравей, стрекоза, таракан и др.)

2. Структура соответствует **примеру преподавателя**:
   - `schema-robot.yaml` — схемы данных (robot-status, move-command, route, pest-detection, multiple-robots)
   - `openapi.yaml` — основной файл с paths и ссылками на схемы

3. Описаны **10 эндпоинтов**:
   - `GET /status` — статус текущего робота
   - `GET /robots` — список всех роботов
   - `GET /robots/{robotId}` — статус конкретного робота
   - `POST /robots/{robotId}/move` — управление движением
   - `GET /robots/{robotId}/route` — получение маршрута
   - `GET /robots/{robotId}/camera/photo` — получение фото
   - `POST /robots/{robotId}/camera/detect` — детекция вредителя
   - `GET /robots/{robotId}/battery` — уровень заряда
   - `POST /robots/{robotId}/maintenance/battery` — замена батареи
   - `POST /robots/{robotId}/reset` — сброс настроек

4. API поддерживает **работу с несколькими роботами** одновременно через идентификатор `robotId`

5. Добавлено поле `species` (вид насекомого) для идентификации типа робота

6. Использован подход **Design API First** — сначала спецификация, потом код

**Изученные технологии:** OpenAPI 3.1.0, YAML, Swagger, Design API First.
