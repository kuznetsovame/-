## Описание задания

Задача № 6: "Robots ".

Создание роботов-насекомых является трудоемкой задачей.Инженеры занимаются проектированием схем в чертежных средах, разрабатывают компоненты для сборки роботов с помощью станков. Программисты отвечают за написание кода для программного обеспечения, которое управляет роботами. Дизайнеры создают внешний вид робота с помощью программных сред. Биологи изучают модель поведения насекомого и отражают результаты в отчетах. Наконец, специалисты по бионике описывают поведение насекомого в виде дифференциальных уравнений, которые программисты добавляют в программное обеспечение.

## Детализация требований в виде пользовательских историй


### ENG — Engineering Context (Инженеры)

- ENG-01-001 : *Я, как заказчик роботов, хочу создать новый прототип робота-насекомого с указанием названия и вида, чтобы начать процесс разработки*

- ENG-01-002 : *Я, как заказчик роботов, хочу загрузить чертёж конструкции в формате CAD, чтобы инженеры могли его использовать для производства*

- ENG-01-003 : *Я, как заказчик роботов, хочу задать технические характеристики (вес, размеры, материал), чтобы робот соответствовал моим требованиям*

- ENG-01-004 : *Я, как заказчик роботов, хочу просмотреть список всех прототипов с фильтрацией по виду насекомого, чтобы видеть, какие роботы находятся в разработке*

### DES — Design Context (Дизайнеры)

- DES-01-001 : *Я, как заказчик роботов, хочу загрузить 3D-модель внешнего вида робота, чтобы дизайнеры могли её доработать*

### BIO — Biology Research Context (Биологи)

- BIO-02-001 : *Я, как заказчик роботов, хочу загрузить биологический отчёт о поведении конкретного насекомого с указанием скорости, рефлексов и реакции на препятствия, чтобы бионики могли его преобразовать*

- BIO-02-002 : *Я, как заказчик роботов, хочу просмотреть все загруженные биологические отчёты по виду насекомого, чтобы отслеживать, какие виды уже исследованы*

### BNC — Bionics Context (Бионики)

- BNC-02-001 : *Я, как заказчик роботов, хочу преобразовать биологический отчёт в дифференциальные уравнения движения (LaTeX), чтобы программисты могли создать прошивку*

- BNC-02-002 : *Я, как заказчик роботов, хочу привязать полученные уравнения к конкретному прототипу, чтобы поведение робота соответствовало реальному насекомому*

### SW — Software Context (Программисты)

- SW-03-001 : *Я, как заказчик роботов, хочу сгенерировать прошивку для робота на основе дифференциальных уравнений, чтобы получить готовое программное обеспечение*

- SW-03-002 : *Я, как заказчик роботов, хочу скачать сгенерированную прошивку в бинарном формате, чтобы загрузить её в робота*

- SW-03-003 : *Я, как заказчик роботов, хочу запустить симуляцию движения робота на основе уравнений и параметров среды, чтобы проверить поведение до начала производства*

### MAN — Manufacturing Context (Производство)

- MAN-04-001 : *Я, как заказчик роботов, хочу создать заказ на производство компонентов для прототипа (указать количество), чтобы запустить производство*

- MAN-04-002 : *Я, как заказчик роботов, хочу отслеживать статус изготовления компонентов по серийным номерам, чтобы знать, когда можно начинать сборку*

### ASM — Assembly Context (Сборщики)

- ASM-04-001 : *Я, как заказчик роботов, хочу получить список готовых компонентов для конкретного прототипа, чтобы понимать, что можно собирать*

- ASM-04-002 : *Я, как заказчик роботов, хочу завершить сборку робота и загрузить прошивку, чтобы получить готового робота с уникальным идентификатором*

## Выводы

1. Сформулированы **17 пользовательских историй** по шаблону «Я как… хочу… чтобы…» — от лица конечного заказчика роботов

2. Выделены **4 эпика**, объединяющие истории по функциональным блокам:
   - Эпик 01 — Проектирование прототипа (ENG, DES)
   - Эпик 02 — Биологические исследования и биомеханика (BIO, BNC)
   - Эпик 03 — Программное обеспечение и симуляция (SW)
   - Эпик 04 — Производство и сборка (MAN, ASM)

3. Внедрена **система нумерации**, где префикс соответствует одному из 7 изолированных контекстов, выделенных в ЛР1:
   - ENG — Engineering Context (Инженеры)
   - DES — Design Context (Дизайнеры)
   - BIO — Biology Research Context (Биологи)
   - BNC — Bionics Context (Бионики)
   - SW — Software Context (Программисты)
   - MAN — Manufacturing Context (Производство)
   - ASM — Assembly Context (Сборщики)

4. Каждая пользовательская история содержит **приёмочное испытание** (неявно в описании — результат, который должен быть достигнут)

5. Детализированы **функциональные требования** к системе разработки и производства роботов-насекомых, которые будут использованы для формирования спецификации OpenAPI в ЛР3

**Изученные технологии:** User Stories, Epics, Acceptance Criteria, Agile Requirements, нумерация требований.
