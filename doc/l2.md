## Наименование работы

Разработка и детализация функциональных требований.

Преподаватель: Фетисов М.В.

Студент группы ИУ6-21М Кузнецова Мария Эдуардовна.

## Описание задания

Задача № 6: "Robots ".

Создание роботов-насекомых является трудоемкой задачей.Инженеры занимаются проектированием схем в чертежных средах, разрабатывают компоненты для сборки роботов с помощью станков. Программисты отвечают за написание кода для программного обеспечения, которое управляет роботами. Дизайнеры создают внешний вид робота с помощью программных сред. Биологи изучают модель поведения насекомого и отражают результаты в отчетах. Наконец, специалисты по бионике описывают поведение насекомого в виде дифференциальных уравнений, которые программисты добавляют в программное обеспечение.

## Детализация требований в виде пользовательских историй

### ENG — Engineering Context (Инженеры)

- ENG-01-001 : *Я, как фермер, хочу чтобы робот-жук передвигался по неровной почве со скоростью не менее 0.1 м/с, чтобы обследовать поле за световой день*

- ENG-01-002 : *Я, как фермер, хочу чтобы робот-жук мог преодолевать препятствия высотой до 3 см (комья земли, небольшие камни), чтобы не застревать в поле*

- ENG-01-003 : *Я, как фермер, хочу чтобы размер робота-жука не превышал 10 см в длину, чтобы он мог передвигаться между растениями, не повреждая их*

- ENG-01-004 : *Я, как фермер, хочу чтобы корпус робота-жука был защищён от пыли и влаги (класс IP54), чтобы он работал в любую погоду*

### DES — Design Context (Дизайнеры)

- DES-01-001 : *Я, как фермер, хочу чтобы робот-жук был зелёного или коричневого цвета, чтобы он был незаметен на поле и не пугал птиц*

### BIO — Biology Research Context (Биологи)

- BIO-02-001 : *Я, как агроном, хочу чтобы робот-жук обходил высокие препятствия (стебли кукурузы) радиусом 10 см, чтобы не застревать в посевах*

- BIO-02-002 : *Я, как агроном, хочу чтобы робот-жук при обнаружении вредителя (колорадского жука) останавливался и подавал сигнал, чтобы я мог обработать это место*

### BNC — Bionics Context (Бионики)

- BNC-02-001 : *Я, как фермер, хочу чтобы робот-жук при столкновении с препятствием менял траекторию на 30–45 градусов, чтобы продолжать движение без остановки*

- BNC-02-002 : *Я, как агроном, хочу чтобы робот-жук обходил участки с повышенной влажностью (лужи), чтобы не застревать в грязи*

### SW — Software Context (Программисты)

- SW-03-001 : *Я, как фермер, хочу чтобы робот-жук работал от одной зарядки не менее 3 часов, чтобы обследовать половину поля без подзарядки*

- SW-03-002 : *Я, как фермер, хочу чтобы робот-жук записывал свой маршрут и передавал его на телефон, чтобы я видел, какие участки поля уже обследованы*

- SW-03-003 : *Я, как агроном, хочу чтобы робот-жук отправлял фото при обнаружении вредителя, чтобы я мог идентифицировать вид и степень заражения*

### MAN — Manufacturing Context (Производство)

- MAN-04-001 : *Я, как фермер, хочу чтобы цена одного робота-жука не превышала 3000 рублей, чтобы я мог купить стаю из 20 штук*

- MAN-04-002 : *Я, как фермер, хочу чтобы робот-жук весил не более 100 грамм, чтобы я мог носить с собой несколько штук в рюкзаке*

### ASM — Assembly Context (Сборщики)

- ASM-04-001 : *Я, как фермер, хочу чтобы робот-жук был готов к работе сразу после распаковки (без настройки), чтобы экономить время в сезон*

- ASM-04-002 : *Я, как фермер, хочу чтобы батарея в роботе-жуке заменялась без инструментов, чтобы быстро менять её в поле*

## Выводы

1. Сформулированы **15 пользовательских историй** по шаблону «Я как… хочу… чтобы…» — от лица **конечных пользователей** (фермер, агроном)

2. Все истории относятся к **одному виду робота** — «робот-жук» для сельскохозяйственного применения (мониторинг полей, поиск вредителей)

3. Выделены **4 эпика**, объединяющие истории по функциональным блокам:
   - Эпик 01 — Проектирование и конструкция робота-жука (ENG, DES)
   - Эпик 02 — Поведение и биомеханика (BIO, BNC)
   - Эпик 03 — Программное обеспечение (SW)
   - Эпик 04 — Производство и сборка (MAN, ASM)

4. Внедрена система нумерации, где префикс соответствует одному из **7 изолированных контекстов**, выделенных в ЛР1

5. Детализированы функциональные требования к системе, которые будут использованы для формирования спецификации OpenAPI в ЛР3

**Изученные технологии:** User Stories, Epics, Acceptance Criteria, Agile Requirements, нумерация требований.
